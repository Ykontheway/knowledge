# 前后端一体化演示路线

目标是做出可以现场演示、结果可核查的 Knowledge CI 工作台：修改知识后，观众能看到版本变化、自动评测结果，以及支持判断的原始证据。本路线以验收结果安排依赖，不承诺未经估算的完成日期。

真实项目文档验收与 B1 只读管理 API 已完成。B2 完成 V3 生命周期与变更视图，B3 完成 V4 只读评测对照与手动导览；V2 静态演示保留。B3 完整回归、隔离 HTTP／jsdom UI 联调及两页页面渲染检查均通过，详见 [评测工作台记录](evaluation-workbench.md#回归命令与验收记录)。B4 受控写交互、B5 MCP 未实现，没有公开 live 部署。版本仍为 `0.1.0` prepared，未创建 tag、PR、main 合并、GitHub Release 或 PyPI 发布。

## 真实文档验收结果

2026-11-13 的隔离运行使用现有 `docs/auto-evaluation.md` 和 `docs/acceptance.md`，导入 11 个知识单元。评测集在首次发布后冻结，共 4 条用例，包含多证据与无答案问题。正向变更、故障注入和恢复均通过正式 CLI 导入触发自动评测。故障时 Recall@5 从 1.0 降到 0.666667，恢复后回到 1.0；失败记录保留，重复导入不产生新任务。

这是项目文档的真实验收，覆盖本机 SQLite 与 lexical 检索。它不证明生产业务效果、模型语义理解、生成答案正确性或完整 Agent 任务成功率。该次验收使用默认绝对质量门禁，没有自动接受基线或宣称已完成 delta 回归。

B1 提供任务、revision、lineage、文档版本 Diff 与精确历史证据的只读契约。B2 接入实时页面，支持任务过滤、分页、手动刷新和 hash 导航。B3 在持久化汇总上增加人工参考／候选对照、指纹与完整性检查、指标解释及阶段导览，仍只读 B1 GET。B1 没有 case-level query／cases，B3 不造逐用例失败诊断。

2026-11-16 的 B3 隔离验收在最终页面修订后复跑通过，run ID 为 `20261116T042018921245Z-951ad2f7`。真实前端 client、运行时 DTO、comparison engine 与 jsdom UI 经 HTTP dev proxy 联调，mean Recall 为 `1 → 0.666667 → 1`。副本 CLI import 后新增 passed 任务能刷新看到，UI 提示、原选择与失败记录保留，临时子进程已停止。报告与复现命令见 [评测对照与演示导览](evaluation-workbench.md)。两页页面渲染检查也通过，控制台为空且内容无外溢；评测页先显示核心结果，导览先显示阶段判定及对照链接。两类验收分别记录，不代表浏览器整链点击或公开部署。

## 产品特色围绕变更展开

工作台从一次知识变更进入，展示该次变更的 revision、关联任务和固定评测集。用户先回答“这次改动是否通过”，再查看相关的知识版本与引用。

- **结果能回到证据**：从评测任务进入版本 Diff，再定位知识单元与原文范围，显示来源、版本及持久化当前状态；该状态不冒充任务当时的 as-of。
- **失败与修复都有记录**：正常、故障、恢复任务由用户手动选择，再核验 CLI 实操。仅有 pass／fail／pass 序列不能证明故障注入，修复也不覆盖失败报告。
- **知识有时间边界**：查看确切文档版本及 lineage 历史，区分 stale、superseded 和退役内容，不用最新正文替换历史证据。
- **指标有适用范围**：dataset pin 与 config fingerprint 一致，报告完整且 checks 门槛相同，才输出 delta。比例差为百分点，null 保留为未评估；不同知识指纹或评测时刻仅作观察，不能自动因果归因。引用覆盖和无答案空检索都不证明 LLM 答案正确。

视觉上保留现有 V2 基础，先保证每个状态能解释、每个数字有来源，再做动效和外观润色。

## 本机演示沿用只读接线

启动命令与安全说明见 [本机只读工作台](live-workbench.md)，HTTP 契约见 [只读管理 API](management-api.md)，B3 路由、对照条件与隔离验收见 [评测工作台](evaluation-workbench.md)。先运行 seed 验收，再把实际输出的唯一运行目录交给 `scripts/live_workbench.py`，不固定某台机器的路径或凭据。Vite Node 与 backend 保存临时 key，浏览器只发同源 GET；preview／dist 不提供 dev proxy。

B2 继续处理 loading、空列表、安全错误、读取重试和完整任务状态，null 不当作零；请求用 Abort 与 sequence 防止旧响应覆盖。B3 选择跨页保留，刷新新任务不替换选择。评测页手动刷新与有界观察共用刷新逻辑，刷新前记录列表头部，再重读当前页和按原 ID 选中的参考／候选；列表或选中任务读取中均视为 busy。导览刷新也重读当前页及已选的正常／故障／恢复任务。

有界观察默认关闭，用户主动开启后每 10 秒刷新，最多 5 分钟／30 次，busy 跳过不延长窗口；隐藏、page key 变化、读取错误或卸载会停止，不自动 resume。停止只影响后续 tick，不承诺取消已发 HTTP，手动刷新仍可用。

B2 历史浏览器验收只覆盖最短导航，没有逐项人工检查全部状态和移动端尺寸。B3 的 jsdom／真实 HTTP 联调与页面渲染检查各有范围；本次云端浏览器无法直达 loopback，未完成浏览器整链点击验收。

## 展示安全与后续能力

自动评测内部报告当前不保存 query 或源全文。B1 不暴露 SQLite 表、私密评测集、绝对路径或任意 payload，原文选段仅在认证后的 evidence 端点明确返回。未来若做用例级诊断，须另行设计隐私与授权契约；当前只提供触发变更与历史证据定位，不宣称根因判断。

当前同步评测会增加变更耗时。现场演示继续使用单库、小规模评测，不把它包装成异步生产服务。后台调度、真实 embedding provider、向量／混合自动评测和 Agent 答案质量评测，分别补 provider 配置、隐私边界、成本与验收数据后再推进。B3 没有新增 LLM 答案评分或生产自治。

外部演示默认使用可公开的项目文档和独立副本；用户业务库只用于经授权的私密验收。公开部署前还需确认认证、数据脱敏、运行可恢复性和服务暴露边界。
